# ARX 控制周期与测量

本页描述 `arx-x5-control 0.6.0` 中 ARX PC 控制器的目标周期和运行统计。实际周期受操作系统、CPU 负载和 CAN 设备影响，应在目标运行环境采集。

## 调度参数

| 环节 | 目标周期 | 说明 |
| --- | --- | --- |
| `LocalLink` 控制循环 | 1 ms | 单调时钟驱动后台线程 |
| 命令和动力学更新 | 2 ms | 更新 TD、轨迹和电机参考值 |
| SDK 反馈发布 | 4 ms | 每台臂独立发布 |
| J1 电机控制 | 2 ms，500 Hz | ENCOS |
| J2～J6 及夹爪控制 | 4 ms，250 Hz | 按相位分散发送 |
| CAN 单帧发送间隔 | 至少 200 μs | 每条总线独立控制 |
| 达妙使能保活 | 每 75 ms 轮流发送一台 | 与周期控制帧分别调度 |

迟到的控制调用执行当前更新，并累计 `missed_command_ticks` / `missed_motor_ticks`。普通目标轨迹每次命令更新推进 2 ms，自动规划按经过时间采样。

应用层每台臂的有效命令间隔须小于 3 s。CAN 持续控制流与进程保活各自执行 100 ms 超时检查；适配器反馈最大接收年龄默认 50 ms。参数和过期处理见 [CAN 接口](CAN_IO.md)。

## 采集运行记录

```bash
# 模拟运行，用于检查统计和记录功能
arx-x5-tui --simulate --log-dir ./logs/arx
# 实机双臂：由操作者按键选择初始化和运行模式
arx-x5-tui --interface socketcan --channel can0 --channel can1 --log-dir ./logs/arx
```

TUI 的记录器在后台写入文件，控制线程与 CAN 线程在内存中累计指标。按 `m` 添加事件标记，可将操作时刻与控制、CAN 和主机负载数据对齐。

| 文件 | 用途 |
| --- | --- |
| `metadata.json` | 主机、内核、Python、包版本、源码哈希和启动参数 |
| `metrics.jsonl` | 周期、耗时、队列和主机资源统计 |
| `events.jsonl` | 控制事件、按键、命令和操作员标记 |
| `control_trace.bin` | 每拍目标、参考值、反馈和输出请求 |
| `summary.json` | 累计统计、最终状态与记录丢弃计数 |

指标采用主机单调时钟，时间字段单位为 ns。字段、二进制格式和统计边界见 [TUI 运行日志](LOGGING.md#tui-运行日志)。

## 结果分析

采样时记录 CPU 调频策略、调度策略、系统负载、连接方式、通道数和运行模式。比较主循环、命令更新与 CAN 周期的分布，同时检查漏拍、过期反馈、队列积压及日志丢弃计数。

CAN 发送时间表示主机传输调用时刻；判断机械臂实际响应应结合反馈时间和位置变化。模拟运行适用于检查统计接口，设备时序需要实机采样。

Metal 的调度参数见 [Metal 控制周期](../metal_arm_control/CONTROL_TIMING.md)。
